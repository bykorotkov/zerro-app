# Messenger MVP (pet project)

План срезанного мессенджера для Zerro. Формат работы: разработчик пишет код сам, техлид (чат) помогает с решениями и задачами внутри
текущего эпика.

Стек: NestJS + Sequelize + Postgres · React · Socket.IO · существующий JWT.

---

## 1. Что делаем

Минимальный работающий мессенджер:

- личные чаты **1-to-1**
- список диалогов
- история сообщений (HTTP + пагинация)
- отправка сообщений в **realtime** (Socket.IO)
- индикатор **«печатает…»**
- **Избранное** (сохранённые) — диалог с самим собой или эквивалент
- простая страница/раздел в UI приложения

Критерий «готово»: два пользователя могут переписываться в realtime, видеть историю и typing, есть избранное.

---

## 2. Что сознательно не делаем

### Коммуникации

- групповые чаты, каналы, роли/админы, инвайт-ссылки
- звонки / видео
- реакции, треды-ответы, пересылка
- редактирование / удаление сообщений (кроме совсем позднего backlog)
- вложения: фото, файлы, голосовые, превью ссылок

### Статусы и доставка

- online / last seen
- галочки «доставлено / прочитано»
- push / email / системный badge

### Продуктовый жир

- полноценный поиск по сообщениям
- секретные чаты, E2E, таймеры удаления
- боты, стикеры, GIF, опросы
- черновики, папки, архив (кроме Избранного)
- модерация, жалобы, блокировка (позже)

### Инфра / масштаб

- Redis, очереди, горизонтальный scale сокетов
- отдельный микросервис чата
- виртуализация на десятки тысяч сообщений
- оффлайн-очередь и сложный sync

### UI

- клон Telegram, отдельное мобильное приложение
- отдельная тема только для чата

Старое клиентское `features/chat` (заточено под `lessonId`) — не целевая модель. Либо выкинуть, либо не смешивать с `conversationId`.

## Эпики (по очереди)

Задачи внутри эпика дробим в чате, когда до него доходим. Ниже — цель эпика и Definition of Done.

### E1 — Модель данных ✅

**Цель:** схема БД под диалоги и сообщения.

- таблицы в духе: `conversations`, `conversation_members`, `messages`
- связи с `users`
- модуль Nest (`ChatModule` / аналог), модели подключены в Sequelize

**DoD:** модели есть, сервер поднимается, таблицы создаются (sync/migration — как принято в проекте).

**Задачи**

1. ✅ Зафиксировать схему полей трёх сущностей
2. ✅ Модель Conversation
3. ✅ Модель ConversationMember
4. ✅ Модель Message
5. ✅ ChatModule + регистрация моделей в app.module
6. ✅ Smoke: сервер поднялся, таблицы есть в Postgres

---

### E2 — HTTP API диалогов и истории

**Цель:** чаты работают без сокетов (Postman / Thunder Client).

- создать / найти личный диалог с пользователем
- список диалогов текущего пользователя
- история сообщений с пагинацией
- auth через существующий JWT

**DoD:** авторизованный пользователь создаёт диалог, пишет сообщение через REST, читает историю.

---

### E3 — Realtime (Socket.IO gateway)

**Цель:** сообщения приходят собеседнику без перезагрузки.

- `@nestjs/websockets` + `socket.io`
- auth сокета по JWT
- комнаты `conversation:{id}`
- событие новой сообщения → сохранить в БД → broadcast в комнату

**DoD:** два клиента онлайн видят сообщения друг друга в realtime.

---

### E4 — «Печатает…»

**Цель:** эфемерный typing-индикатор.

- `typing:start` / `typing:stop` (или одно событие + TTL на клиенте)
- **не** пишем typing в БД
- debounce на клиенте

**DoD:** пока собеседник печатает, видно индикатор; после паузы он пропадает.

---

### E5 — Клиентский UI

**Цель:** пользоваться чатом из приложения, не только из Postman.

- страница/раздел мессенджера в роутинге
- список диалогов + окно переписки
- один socket на приложение (не на каждый виджет)
- отправка + подгрузка истории
- базовые стили в духе текущей темы приложения

**DoD:** сценарий «открыл UI → выбрал/создал чат → переписка» работает end-to-end.

---

### E6 — Избранное (сохранённые)

**Цель:** место для заметок себе.

- диалог «с собой» или тип/флаг `saved`
- отображение в списке диалогов

**DoD:** пользователь пишет в Избранное и видит историю там же.

## Правила ведения

1. Идём **строго по одному эпику**.
2. Не тащим фичи из «не делаем», пока MVP не закрыт.
3. После эпика — обновляем блок «Где мы сейчас».
4. Детальные задачи на спринт/вечер придумываем в чате под активный эпик.
